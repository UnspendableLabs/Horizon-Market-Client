# Generated Kontor contract bindings

`token.ts` and `nft.ts` are generated by `kontor-codegen` — the `bin` of `@kontor/sdk`,
so the generator always matches the installed SDK — from the native contracts' source
WIT in the Kontor repository. Do not hand-edit.

Regenerate them after bumping `@kontor/sdk` (codegen output changes between releases:
0.3.0-rc.7 made writes resolve to their success value and added cursor pagination), or
when the network's token / NFT contract ABI changes:

```sh
KONTOR=../Kontor        # a checkout of github.com/KontorProtocol/Kontor
REF=305a4210            # the Kontor commit the SDK release was cut from
for c in token nft; do
  git -C "$KONTOR" show "$REF:native-contracts/$c/wit/contract.wit" > "$TMPDIR/$c.wit"
  npx kontor-codegen "$TMPDIR/$c.wit" -o "src/kontor/__generated__/$c.ts"
done
```

Use the contract **source** WIT. The node's `GET /api/contracts/{token,nft}_0_0` serves
a public WIT without `init` (and the token's core-only exports), which `kontor-codegen`
rejects — but compare its exports with the source's before regenerating: every function
it lists must appear in the source with the same signature, or the bindings would encode
calls the network refuses.

Current files: `@kontor/sdk` 0.3.0-rc.8, Kontor `305a4210`. The contract WIT there is
identical to `9f5779f2`, the protocol the relaunched signet runs, and matches the live
`https://signet.kontor.network:35000/api` export for export.

The Horizon-Market server keeps its own copy under
`src/lib/clients/kontor/__generated__/`; regenerate it the same way when it bumps the SDK.
